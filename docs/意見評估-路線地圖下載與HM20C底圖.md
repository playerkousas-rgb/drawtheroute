## 2. 意見①：下載「路線連地圖」圖片

### 2.1 實用性 ★★★★★

現有用家流程：APP 規劃路線 → 另外搵／買／掃描地圖 → 手畫路線上去。
意見①將後半段完全喺 APP 內完成：**一鍵下載「底圖＋路線＋CP」圖片**，直接列印或傳俾隊友，掃描步驟蒸發。

最有價值嘅用家情境：
- 領隊出發前印 A4/A3 紙圖帶上山（手機無電都有圖睇）
- 童軍／定向活動製作路線圖（正正是 HKMAP 用家嘅姊妹需求）
- 報告、路線分享帖（GPX 之外要埋「睇得明」嘅圖）

### 2.2 可行性 ★★★★☆

**建議方案：手寫 canvas 拼圖，唔用 html2canvas 截地圖。**

| 方案 | 說明 | 評價 |
|------|------|------|
| A. html2canvas 截 `leaflet-container` | 最快上手 | ❌ Leaflet 嘅 `translate3d` 瓦片定位喺 html2canvas 1.4 有已知錯位問題；截埋 UI 雜物；解像度唔可控 |
| **B. 手動 canvas 拼接（建議）** | 按目標 bounds＋像素，用 `L.CRS.EPSG3857` 計算瓦片座標逐塊 `drawImage`，再投影畫路線／CP／比例尺 | ✅ 零新依賴（純 Canvas API）、輸出乾淨、可控制 DPI／尺寸、可加圖框元素；約 200 行 |

方案 B 輸出內容建議（v1）：
1. 當前視窗範圍嘅底圖（可選 1x / 2x 解像度）
2. 路線（現有路線樣式：主色＋邊）＋ CP 標記＋編號
3. 比例尺、指北針、簡單 HK80 方格（可開關）
4. 標題列（路線名／日期）＋**必須有嘅版權標示**（見 §4）
5. PNG 下載（`file-saver` 或 `<a download>` 現成）

### 2.3 風險與守則

| 風險 | 影響 | 緩解 |
|------|------|------|
| **瓦片 CORS**（canvas 匯出要 `crossOrigin='anonymous'`，若圖磚 server 冇 `Access-Control-Allow-Origin`，canvas 會 tainted，`toBlob` 拋 SecurityError） | 呢個係**唯一真正未知數** | P0 spike：逐個底圖源驗證；`L.tileLayer(url, { crossOrigin: 'anonymous' })`；失敗時明確提示＋只保留可行底圖嘅匯出選項 |
| 圖磚請求量（A4@300dpi ≈ 100+ 塊瓦片瞬間拉取） | OSM／LandsD 都有「唔好短時間大量請求」條款 | 併發限制（≤6）、完成後靠瀏覽器 cache、解像度上限（如長邊 ≤ 8192px）、連點防抖 |
| 高解像 canvas 記憶體 | 極大圖偶發崩潰 | 長邊上限 8192px；300dpi 預設（**桌面規劃工具，手機非目標平台**，唔為手機降級） |
| 期望管理 | 用家以為「下載」＝GeoPDF／可編輯 GIS 檔 | v1 明確係「圖片」；見 §5 低成本加分項 |

### 2.4 成本

約 **2–4 天**：匯出模組（1.5–2 天）＋ 疊加元素（比例尺／指北針／格網／標題 0.5–1 天）＋ 各底圖 CORS 驗證與 fallback（0.5 天）＋ 桌面實測（0.5 天）。**零新 npm 依賴**，完全符合瘦身守則。

## 3. 意見②：HM20C 底圖

### 3.1 先講清楚「HM20C 底圖」是什麼

- **HM20C** = 地政總署測繪處 1:20,000 地形圖系列（H=Topographic、M=Map、20=1:20,000、C=有等高線），16 張圖幅、20 米等高距、五種專色印刷，香港行山／童軍嘅「標準紙圖」，每張約 HK$26–62。
- **紙本 HM20C 係有版權印刷品，坊間冇公開掃描圖磚**——呢點倉主喺 HKMAP repo 已查證過。
- 官方對應電子產品係 **iB20000 數碼地形圖**（2021 年起免費下載；FGDB/GML/DWG/DGN/GeoTIFF）。
- **可行做法**：地政總署 **LandsD Map API · Topographic Map API**——正正係由 iB20000 渲染出嚟嘅 XYZ 圖磚：

```
https://mapapi.geodata.gov.hk/gs/api/v1.0.0/xyz/basemap/WGS84/{z}/{x}/{y}.png   （z10–20）
```

  另有 Map Label API（中／英地名疊加）同 Imagery Map API（官方航拍）。WGS84 版直接相容 Leaflet（HKMAP 同 HK GeoTiles 教學都實證過）。

**期望管理**：內容（道路、小徑、等高、地貌、地名）與 HM20C 同源，但係數碼渲染風格，**唔係紙本五專色＋手繪山影嘅觀感**。對實用（搵路、睇地形）係一致嘅，對「要一模一樣紙本」嘅用家要講明。

### 3.2 實用性 ★★★★★

- OpenTopoMap 係全球資料，香港小徑／地物詳情遠不及官方 iB20000（山徑、涼亭、標距柱級別嘅細節）。
- 行山用家嘅肌肉記憶就係 HM20C 風格：等高線 20 米、雙語地名。呢個底圖對「行山 APP」定位係**身份級**加成，唔係錦上添花。

### 3.3 可行性 ★★★★★

| 選項 | 觀感 | 成本 | 結論 |
|------|------|------|------|
| **A. LandsD Topographic Map API 圖磚** | iB20000／HM20C 同源渲染 | ≈ 加一個 `MapLayer` 值＋`TILES` 一條＋工具列一粒掣 | ✅ **建議** |
| B. 疊加中文地名（Map Label API `.../xyz/label/hk/tc/WGS84/{z}/{x}/{y}.png`） | 補地名 | 一行 overlay | spike 後決定（basemap 若已含地名就唔使） |
| C. 等高線 overlay（HKMAP 做法：Esri China (HK) 公開 iB20000 `ELEVLINE` 圖層） | 可開關等高線 | 中 | P2 可選 |
| D. 自架 iB20000 GeoTIFF 切片 | 最忠實 | 巨大 storage＋bandwidth | ❌ 違反瘦身守則 |
| E. 掃描紙本 HM20C | 一模一樣 | 版權侵權＋冇貨源 | ❌ 不可行 |

改動面（方案 A）：
- `src/types/index.ts`：`MapLayer` 加 `'hm20c'`
- `MapCore.tsx` `TILES`：加一條（`maxZoom: 20`）
- `LeftToolbar.tsx`：加「HM20C 地形圖（地政）」掣（第四粒，跟現有三粒排法）
- Attribution：`Map from Lands Department`（見 §4）
- 全部係設定級改動，**近乎零體積、零風險**，同現有三層完全一致嘅切換邏輯。

### 3.4 成本

**0.5–1 天**（含版權標示、README 條款註記、真機試圖磚速度）。

## 4. 版權與條款（兩項意見共用，必須跟）

LandsD Map API 條款重點（[TNC](https://portal.csdi.gov.hk/csdi-webpage/doc/TNC) + [Topographic Map API](https://portal.csdi.gov.hk/csdi-webpage/apidoc/TopographicMapAPI)）：

1. **可**免費商用／非商用瀏覽、下載、複製、分發——即「匯出含地圖嘅圖片」**合法可行**。
2. 圖面上要標示 **`Map from Lands Department`** 版權告示，條款亦寫明要包含地政總署 logo（建議：螢幕 attribution 行＋匯出圖片角落都放；logo 檔案可向 mapapi@landsd.gov.hk 確認規格，先用文字告示起步——HKMAP 已係咁做）。
3. **唔可以短時間大量請求 API**——直接影響①嘅匯出設計（見 §2.3 緩解）。
4. OSM（ODbL）／Esri／OpenTopoMap 各自嘅 attribution 繼續保留喺匯出圖片入面。
5. README 加「使用前請同意 LandsD Map API 條款」一行，跟 HKMAP 慣例。

## 5. 整個 APP 的平衡

### 5.1 產品定位平衡（最重要）

DrawTheRoute 嘅身份 = **行山路線規劃＋高程分析＋行程表**。呢兩項意見都係「規劃完成後嘅產出」，係補完唔係偏航：

- ✅ 應做：「路線＋地圖圖片」作為 GPX／Excel／剖面圖之外**第四種匯出物**——同一件事（規劃結果）嘅唔同載體。
- ❌ 唔好做（留俾 HKMAP）：鎖比例 WYSIWYG 排版印刷、A3 多頁拼接、檢查點說明表列印——呢啲係 HKMAP（城市定向紙圖）嘅主場，DrawTheRoute 做咗只會兩邊重疊、維護雙倍。
- ❌ 唔好做：離線地圖包下載、3D、PDF 匯出（jspdf 已被瘦身守則點名禁止；要 PDF 就用瀏覽器「列印→PDF」，零成本）。

### 5.2 瘦身守則平衡

| 項目 | 評估 |
|------|------|
| npm 體積 | **+0**（canvas 純手寫；file-saver／html2canvas 現成） |
| bundle | `TILES` 加一條＋匯出模組 ≈ 6–8KB，遠低於守門紅線 |
| Vercel bandwidth | 匯出係用家瀏覽器直接拉圖磚，唔經 Vercel；無影響 |
| `check:slim` | 無新增靜態大檔，通過 |

### 5.3 UI 平衡

- 工具列：底圖掣由 3 變 4（一行排得落）；「匯出」group 加一粒「下載路線地圖 PNG」，disabled 條件同 GPX（有路線先可按）。
- 複雜度：匯出預設「所見即所得」（當前視窗、當前底圖），進階選項（解像度／格網／標題）收喺一個小 popover，唔污染主介面。

### 5.4 維護風險平衡

- 圖磚 API 有版本風險（條款寫明「舊版本可隨時移除」）——URL 寫死 `v1.0.0` 並集中喺 `TILES` 一處，方便改版；政府服務可用性歷史良好。
- ①嘅匯出模組係自研約 200 行 canvas 代碼，比引第三方截圖庫更可控，測試面細（單元測試可驗投影數學）。

## 8. 追問①：路線唔喺 HM20C 上，點處理？

**問題本質**：HM20C／iB20000 只收錄地政總署測繪咗嘅路徑；但香港大量行山線係非正式山徑（獸徑、季節徑、新路），OSM 有用家記錄、官方圖冇。仲有反向情況：HM20C 有嘅小徑 OSM 冇，BRouter「磁石貼路」會貼唔到。兩邊永遠唔會 100% 一致。

**先講結論：呢個問題紙本時代一樣存在，而且行山人一直有解——「條線本身先係權威」。** 手繪路線喺 HM20C 上照樣跨過空白地帶照用，讀者跟嘅係畫出嚟嗰條線，唔係底圖嘅路徑。所以：

### 8.1 畫得出（P1 必做，零成本）✅

- 路線係**用家資料**，永遠疊喺最頂（`MapCore` 已有 glow/casing 雙層樣式），底圖有冇路徑都照顯示。
- 匯出圖圖例加一行：**「路線為規劃／實測線，部分路段可能未見於地形圖」**——同紙本手繪路線嘅用法一致，管理讀者期望。
- 樣式守則：高對比主色＋深色邊＋（可選）CP 編號，確保喺任何底圖、黑白列印下都清晰。

### 8.2 睇得明（按成本階梯，揀嚟做）

| 方案 | 做法 | 成本 | 建議 |
|------|------|------|------|
| **B. 疊圖模式** | 匯出時喺 HM20C 上面再畫一層現有 OSM／OpenTopoMap 瓦片（30–50% 透明度）——「HM20C＋山徑疊圖」一圖睇晒兩套路徑；attribution 加 OSM | **極低**（canvas 插圖器順手畫第二層瓦片啫） | ✅ P1.5 強烈建議 |
| C. OSM 山徑矢量疊加 | Overpass 查 `highway=path/track`（bbox）→ 畫成細虛線；只顯示路徑、唔會整污糟底圖 | 中（多一個外部服務；可用 BRouter 同類 fallback 策略） | P2 |
| D. 自動標示「非地圖路段」 | 將路線點同地圖路徑幾何比對，偏離超過閾值嘅 segment 用警示色／虛線＋圖例註記 | 高（要兩套路徑幾何＋演算法） | P2 之後，見回報需求先做 |
| E. 「強制貼 HM20C」路由 | 重新按 iB20000 路徑做 snap | **不建議**——非正式山徑正正唔喺 iB20000，強制貼圖會令路線失真，違反用家意圖 | ❌ |

### 8.3 反向 mismatch（HM20C 有路、OSM 冇）

- 磁石貼路貼唔到就用**手繪＋手動微調**（現有功能已覆蓋），線照樣畫得出。
- 疊圖模式（方案 B）反而幫手：見到 HM20C 有路但條線冇貼到，用家自己拉過去。
- **唔好追求「官方路徑權威圖」**——冇邊套係權威，用家條線先係權威。APP 嘅職責係「幫用家畫出、畫清楚」，唔係「判斷條路存唔存在」。

## 9. 追問②：圖幅大過 A4，點處理？

**先拆穿一個誤會：匯出係「圖片」，唔受 A4 限制。** 掃描取代嘅係「有路線嘅地圖內容」，唔係「一張 A4 紙」。PNG 可以係 A2 咁大，拎去列印店輸出（A3 幾蚊、A2 十幾蚊），或者手機開圖都睇到全線。

### 9.1 先睇數字：其實好多路線「過 A4」係比例問題，唔係面積問題

以 300dpi 計，唔同比例下紙張覆蓋嘅實際範圍：

| 比例 | A4（210×297mm） | A3（297×420mm） | A2（420×594mm） |
|------|----------------|----------------|----------------|
| 1:20,000（HM20C 同比例） | 4.2 × 5.9 km | 5.9 × 8.4 km | 8.4 × 11.9 km |
| 1:25,000（郊區地圖） | 5.3 × 7.4 km | 7.4 × 10.5 km | 10.5 × 14.9 km |
| 1:40,000 | 8.4 × 11.9 km | 11.9 × 16.8 km | 16.8 × 23.8 km |

→ 香港大部分**一日行程（8–15km）**：A3 @ 1:20,000 或 A4 @ 1:40,000 就包得晒。真正大過晒所有單頁嘅係長征路線（例如麥理浩徑全長 100km）——嗰啲係「分段圖」需求，唔係「一張圖」需求。

### 9.2 P1 匯出面板設計（三招解決「大過 A4」）

1. **範圍**：「整條路線（自動 fit，預設）」/「當前視窗」/「自選框」
   - 自動 fit = 以路線 bbox 加 margin 置中，一鍵出**全線總覽圖**（行山 briefing 嘅真實需求）
2. **比例**：「自動（fit 到輸出尺寸）」/ 1:20,000 / 1:25,000 / 1:40,000
   - 固定比例時若路線超出覆蓋：顯示「⚠ 此比例只能覆蓋約 X×Y km」＋一鍵「改用自動 fit」，**唔好靜靜雞切走一半路線**
3. **輸出尺寸**：A4 / A3 / A2 @ 300dpi 預設（列印級），或自訂像素（長邊上限 8192px）
   - A2 單圖 = 6600×9300px 級別；**規劃＝電腦工作**，桌面向輸出，唔為手機降級

### 9.3 超長路線（真正裝唔落任何單頁）

| 方案 | 說明 | 建議 |
|------|------|------|
| **手動分段匯出** | 用「當前視窗／自選框」模式逐段出圖（用家自己控制分段點） | ✅ P1 已涵蓋，零額外成本 |
| 自動分頁（圖幅式，有重疊＋索引圖） | mapbook 式多頁 A4 | P2；屬 HKMAP「WYSIWYG 分頁列印」地盤，做之前先傾分工 |
| GeoPNG＋`.pgw` world file | GIS 用家入 QGIS 任意尺寸排版（呼應 HKMAP QGIS 教學 workflow） | ✅ 平靚正加分項，一個 text file 嘅成本 |
| 瀏覽器「列印→PDF」 | 零依賴出 PDF | 提示用家即可，唔使做進 APP |

### 9.4 對 §6 路線圖嘅修訂

- **P1.5 加入**：疊圖模式（§8.2 方案 B）
- **P2 加入**：GeoPNG world file、自動分頁（先同 HKMAP 分工）、OSM 山徑矢量疊加

## 10. 追問③：3日2夜／4日3夜——「能放進」≠「能用」

**完全同意呢個批評。** 1:100,000 放得落全港、路線幾何又準，但行軍時冇用——睇唔到小徑、等高線太疏、量唔到方位。所以「自動 fit」只係**總覽模式**，唔可以當行軍圖。多日童軍行程（30–70km）嘅正確解法係**「可用比例＋自動分段」**，唔係「一張更細嘅圖」。

### 10.1 設計原則：先定「能用」，再定輸出

| 原則 | 規格 |
|------|------|
| **可用比例帶** | 1:15,000–1:40,000（HM20C＝1:20,000、郊區地圖＝1:25,000 係黃金標準）。自動 fit 出嚟如果比例分母 > 40,000，對話框直接警告「只可作總覽」 |
| **比例誠實** | 自動 fit 一律顯示「輸出約 1:N」（用家要求：fit 並告知比例）；固定比例模式圖面印明「1:20,000（100% 列印）」 |
| **實尺寸輸出** | 圖按 A3/A4 @200/300dpi 生成——100% 列印即係該比例，可直接用比例尺／指南針做定向（童軍訓練需要） |
| **分段唔係降級** | 長線出多頁圖幅，每頁保持可用比例；唔係將成條線縮細塞落一頁 |

### 10.2 「固定比例＋自動分段」規格（圖幅式 mapbook）

- **分頁演算法**：固定比例軸向格網，沿路線推進，頁間 **20% 重疊**；只輸出同路線相交嘅頁，按「首次相交距離」排序（跟行軍次序）
- **每頁內容**：該段路線高亮（全線 ghost 淡化＋該頁區間主色）、CP 編號、比例尺、指北針、標題帶（`頁 3/8 · 12.4–18.1 km`）、版權行
- **尺寸實例**：A3 橫向 @1:20,000 ＝ 每頁 8.4×5.9 km；40km 日程 ≈ 5–8 頁；3日 50km ≈ 8–12 頁
- **輸出**：逐頁下載 PNG（瀏覽器詢問「允許多個下載」）；列印時 100%＝1:20,000
- **演算法已實裝**（`planRoutePages`／`exportRoutePages`）；對話框即時顯示「將輸出 N 頁」

### 10.3 各模式定位（對話框四選一）

| 模式 | 用途 | 對應「能用」 |
|------|------|--------------|
| 整條路線（自動 fit） | briefing 總覽、WhatsApp 分享 | ⚠ 比例過細會警告；顯示 1:N |
| 當前視窗 | 手動框選局部、微調輸出 | 用家自己控制 |
| 固定比例單頁 | 局部行軍圖（5–8km 範圍） | ✓ 精確 100% 列印 |
| **固定比例＋自動分段** | **多日長線（3日2夜／4日3夜）行軍圖冊** | ✓ 每頁保持可用比例 |

### 10.4 邊界情況

- **路線跨頁**：重疊 20%＋頁內高亮，接圖睇得順
- **一日之內多日分組**：v1 頁標用距離區間；行程表已有「第 N 日」結構，P2 可加「按日分頁組」（每日第一頁加日頭）
- **A3 都太大**（單日 >8.4km 直向轉唔到）：輸出多頁即係分段模式本身
- **平台定位**：**桌面規劃工具**——3日2夜／4日3夜呢類計劃，連電腦都唔用係自找麻煩；預設 300dpi 列印級，唔為手機降級解像度或功能。手機只求「開到睇到」，唔係優化對象
- **唔做**：鎖比例 WYSIWYG 編輯（HKMAP 地盤）、PDF（瀏覽器列印已夠）
